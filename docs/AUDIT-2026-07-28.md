# Аудит KROT zapret — 2026-07-28—29

## Итог

Репозиторий приведён к состоянию локального MVP для двух сценариев:
Discord и YouTube. Обычные Debug/Release-сборки используют реальный runtime;
демонстрационный runtime включается только явными аргументами.

Локальная служба больше не должна постоянно работать после закрытия GUI.
Проверены обычное завершение через `shutdown` и аварийное завершение по
15-секундному тайм-ауту heartbeat.

## Исправленные критические и высокие риски

- Debug-служба от `LocalSystem` больше не запускается из пользовательского
  каталога репозитория. Скрипт копирует сборку в защищённый каталог
  `%ProgramFiles%\KROT zapret Dev\service`.
- GUI и установленная служба больше не подменяют реальный runtime имитацией в
  Release. Для демонстрации оставлены только `KROT.exe --demo` и
  `KROT.Service.exe --fake-runtime`.
- Служба переведена в `Manual`, запускается GUI по требованию и завершается
  вместе с ним. После аварийного исчезновения GUI watchdog останавливает runtime
  и службу.
- IPC принимает до четырёх одновременных клиентов, поэтому `status` и `stop`
  работают во время длительного подбора профиля.
- Служба отслеживает все принятые IPC-задачи, закрывает активные Named Pipe при
  отмене и дожидается обработчиков. Это устраняет зависание чтения Pipe в
  .NET Framework при остановке.
- IPC-запрос ограничен 16 KiB и 5 секундами чтения; ответ клиента — 1 MiB и
  конечным тайм-аутом. Некорректный UTF-8 и слишком большие сообщения
  отклоняются.
- Активный подбор профиля отменяется командой `stop`; GUI продолжает показывать
  этапы запуска и предлагает кнопку «Отменить».
- Устранена гонка фонового health monitor: остановка дважды проверяет монитор
  вокруг engine-gate, отменяет его и дожидается завершения до очистки сессии.
- Все исполняемые файлы и все rooted-входы реально используемых встроенных
  стратегий (hostlist, WinDivert-фильтры, TLS/QUIC/Discord blobs) покрыты
  SHA-256-манифестом. Запуск входа, отсутствующего в проверенном манифесте,
  запрещён.
- Исправлено освобождение объектов `Process` после завершения `winws/winws2`.
- Базовые события и ошибки журналируются всегда; подробный режим добавляет
  только сетевые пробы, перебор стратегий и stdout runtime. Переключатель
  меняет GUI и службу сразу, в том числе во время работающей сессии.
- Каждый журнал строго ограничен пятью файлами по 2 MiB. Одиночные сообщения и
  исключения обрезаются, переносы обезвреживаются, параллельные записи
  сериализуются, а ошибка записи журнала не ломает остановку приложения.
- Каталог `%ProgramData%\KROT zapret\service-state` защищён: запись разрешена
  только `SYSTEM` и администраторам, обычным пользователям оставлено чтение.
- Исправлена миграция ACL вложенных файлов `service-state`. Рекурсивное
  применение наследуемых ACE могло оставить старые логи и preset-cache с
  пустым ACL, из-за чего реальный `start` завершался ошибкой без доступного
  журнала. Установщик теперь защищает корень, затем сбрасывает ACL детей для
  безопасного наследования; существующая Debug-установка успешно восстановлена.
- Размер читаемых настроек и preset-cache ограничен 1 MiB; чрезмерный или
  повреждённый JSON безопасно отбрасывается.
- Повреждённые или частично `null`-настройки нормализуются; при повреждении
  основного файла используется резервная копия или сохраняются безопасные
  значения по умолчанию.
- Сетевой отпечаток дополнен адресами шлюзов, DHCP-серверов и сетевыми
  префиксами, чтобы меньше смешивать сохранённые профили разных сетей.
- После остановки последнего KROT-процесса менеджер останавливает только тот
  kernel-driver `WinDivert`, чей зарегистрированный путь совпадает с
  проверенным runtime KROT. Оставшийся от старого Debug-запуска драйвер был
  найден и безопасно выгружен; активный VPN на Wintun не затронут.
- Закрытие GUI имеет отдельный короткий тайм-аут и не запускает уже остановленную
  службу только ради `shutdown`. Консольный host также гарантированно
  останавливает engine и освобождает Job Object.
- Удаление через Inno Setup теперь дожидается остановки службы перед удалением,
  а при согласии пользователя удаляет также служебные логи и preset-cache.
- CI имеет только `contents: read`, собирает с `TreatWarningsAsErrors`, запускает
  тесты и проверяет уязвимые зависимости. Публикация артефактов и релизов
  отключена до готовности дистрибутива.

## Выполненные проверки

- Debug x64: сборка без предупреждений и ошибок.
- Release x64: сборка без предупреждений и ошибок.
- `TreatWarningsAsErrors=true`: успешно в обеих конфигурациях.
- На базовом прогоне: 50/50 тестов успешно в Debug и 50/50 в Release.
- После добавления обновлений, сетевого мониторинга, ротации логов и
  service-тестов: 65/65 успешно в финальном Debug-прогоне.
- Style/analyzer-проверки: успешно.
- NuGet vulnerability scan с transitive-зависимостями: известных уязвимостей
  нет.
- Хэши runtime-манифеста и всех используемых входов: успешно.
- Живой цикл `start → status → stop → shutdown`: успешно,
  `IsFakeRuntime=false`, остаточных `winws/winws2` нет.
- Живой watchdog без heartbeat: служба с работающим runtime завершилась за
  16,2 секунды; после неё не осталось процессов и WinDivert-драйвера.
- ACL локальной Debug-установки: запись только `SYSTEM` и администраторам;
  обычным пользователям — `ReadAndExecute`.
- Service DACL: интерактивным пользователям разрешены только запрос состояния,
  запуск и остановка; изменение конфигурации не разрешено.
- ACL `service-state` и вложенного каталога логов: `SYSTEM/Administrators =
  FullControl`, `Users = ReadAndExecute`. Те же наследуемые права проверены
  непосредственно на существующем файле журнала.
- Автономные service/IPC-тесты: параллельные `start/status/stop`, отмена
  запуска, очистка owned-процессов, дожидание подключённого Pipe-клиента,
  немедленное изменение подробного режима — успешно.
- Service-тесты изолированы уникальными именами Named Pipe и больше не
  перехватываются работающим экземпляром GUI.
- Проверка при включённом VPN обнаружила `happ-tun`, `sing-box` и `xray`.
  Чтобы не отключать VPN рабочего сеанса, только текущие IPv4-адреса
  Discord/YouTube временно направлялись напрямую через Wi-Fi. Контроль без
  KROT: DNS/TCP успешно, TLS и HTTP у обоих сервисов завершились тайм-аутом.
  С реальным KROT (`IsFakeRuntime=false`): Discord — TLS OK, HTTP 200;
  YouTube — TLS OK, HTTP 204. Все 13 временных `/32`-маршрутов удалены,
  служба остановлена, процессов/драйвера не осталось, `happ-tun` остался `Up`.
- Каталог полевого теста приведён к границам MVP: проверяются только Discord
  и YouTube; несвязанный endpoint `chatgpt.com` удалён.
- Discord Voice проверен отдельно с включённым системным VPN, но прямой
  маршрутизацией только Discord edge/RTC. После переподключения внешний адрес
  RTC сменился с VPN на адрес провайдера, состояние дошло до `RTC_CONNECTED`,
  а runtime зарегистрировал победивший профиль
  `KROT_UDP_WINNER|discord_voice|voice-01-fake-r2`.
- GUI-smoke пройден: главный экран содержит только автозапуск, Discord, YouTube
  и основную кнопку; язык, подробные логи, просмотр логов и ссылки находятся в
  информационной панели. Штатное закрытие окна завершило GUI, runtime и службу.

## Оставшиеся ограничения перед распространением

1. GUI, служба и установщик не подписаны Authenticode. Для публичного выпуска
   нужны сертификат, подпись и проверка подписи в release-процессе.
2. Inno Setup отсутствует на машине аудита, поэтому обновлённый `.iss` и
   установщик не были скомпилированы. PowerShell-скрипт установки службы
   проверен отдельно.
3. Нужны чистые ручные/автоматические прогоны на Windows 10 22H2 и актуальной
   Windows 11, включая установку, обновление и удаление.
4. Named Pipe ориентирован на активного console-пользователя. RDP и несколько
   одновременно вошедших пользователей требуют отдельной модели сессий.
5. Любой интерактивный пользователь локального компьютера может запустить или
   остановить общую службу. Это приемлемо для однопользовательского MVP, но
   должно быть сужено для multi-user выпуска.
6. Runtime-манифест защищён ACL установленного каталога, но сам не имеет
   криптографической подписи. Администратор машины остаётся доверенной стороной.
7. В комплекте лицензий есть тексты Zapret и WinDivert, но перед публикацией
   нужно добавить локальные тексты лицензий Cygwin, CommunityToolkit.Mvvm и
   Newtonsoft.Json, а не только ссылки в notices.
8. GitHub Actions используют version tags, а не commit SHA. Перед включением
   публикации actions следует закрепить по проверенным SHA.
9. Нет UI-автоматизации для WPF, проверки screen reader/keyboard navigation и
   визуального регрессионного теста.
10. Работоспособность Discord Voice напрямую через провайдера подтверждена.
    Однако L7-фильтр `discord,stun` теоретически может обработать общий
    STUN-трафик других приложений. Перед сужением фильтра или публичным выпуском
    нужна отдельная проверка одновременной работы других WebRTC-приложений.
11. Production-проекты не используют deprecated NuGet-пакеты, но тестовые
    проекты остаются на xUnit v2, который NuGet теперь помечает `Legacy`.
    Миграцию на xUnit v3 разумно выполнить отдельно, не смешивая её с runtime.

## Локальное состояние после аудита

- Служба `KROTZapret`: `Stopped`, `Manual`.
- Путь службы:
  `C:\Program Files\KROT zapret Dev\service\KROT.Service.exe --real-runtime`.
- Процессы `winws.exe`, `winws2.exe`, `KROT.Service.exe`: не запущены.
- Динамический driver-service `WinDivert`: не загружен и удалён системой после
  остановки; VPN-адаптер `happ-tun` остался `Up`.
- Исходники подготовлены как checkpoint версии `1.0`; установщик и GitHub
  Release этим аудитом не создаются.
