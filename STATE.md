# Состояние проекта KROT zapret

Актуально на 28 июля 2026 года. Этот файл — основная точка входа для продолжения
работы в новом чате. Сначала читать его, затем `README.md` и
`docs/ARCHITECTURE.md`.

## 1. Коротко о проекте

KROT zapret — локальное Windows-приложение для запуска и автоматического подбора
стратегий Zapret отдельно для Discord и YouTube.

Основные ограничения продукта:

- это не VPN и не прокси;
- собственных удалённых серверов нет;
- Telegram из проекта исключён;
- отдельного сервиса нейросетей в проекте больше нет;
- пользователь выбирает только Discord и/или YouTube;
- GUI работает без повышения прав;
- привилегированные `winws`/`winws2` запускает Windows Service;
- KROT завершает только те процессы, которыми владеет сам.

Текущая версия интерфейса — `0.1.0-alpha`. Рабочая разработка пока ведётся
локально в Debug. Удалённый `origin` настроен на
`https://github.com/morda-mir/KROT-zapret.git`, но текущий большой checkpoint
нужно держать локальным до отдельного решения о публикации.

## 2. Что уже работает и подтверждено

### Discord

- TCP/TLS: текст, API, основные страницы.
- Медиа/CDN: отдельный профиль с дополнительными Discord-портами.
- Voice/STUN: отдельный процесс Zapret 2.
- Голосовой Discord реально проверен без VPN.
- Получен реальный маркер:
  `KROT_UDP_WINNER|discord_voice|voice-01-fake-r2`.
- После маркера голосовой индикатор действительно стал зелёным в GUI.
- Discord Voice использует динамический UDP-порт из Ready payload.
- Исходящий IP Discovery request и первый входящий response перехватываются
  точными WinDivert-фильтрами независимо от номера UDP-порта.

### YouTube

- Сайт и TCP-видеопоток работают через профиль Zapret 1.
- QUIC/HTTP3 вынесен в адаптивный UDP-профиль Zapret 2.
- В каталоге есть восемь QUIC-стратегий.
- Полевая проверка сайта и видео пользователем проходила успешно.
- Подтверждение конкретного QUIC-победителя в последней сессии отдельно не
  фиксировалось.

### Сеть и мониторинг

- VPN определяется по активным адаптерам, типу интерфейса, маркерам имени и
  системному прокси.
- При обнаруженном VPN автоматический TCP-перебор не запускается.
- Плановый health-check выполняется раз в 90 секунд.
- Смена VPN, Wi-Fi или другого сетевого адаптера теперь немедленно будит
  монитор.
- После сетевого события выдерживается две секунды на стабилизацию.
- После восстановления всего интернета выдерживается ещё восемь секунд перед
  проверкой активного пресета.
- Полный обрыв интернета не считается отказом Discord/YouTube и не запускает
  ложный перебор.
- TCP-ремонт запускается только после двух последовательных отказов конкретного
  сервиса при доступном общем интернете.

### Исправленный ложный Discord-тест

Раньше служба проверяла только
`https://discord.com/api/v10/gateway`. На рабочем Discord этот URL мог дать
таймаут, из-за чего KROT перебирал все 16 TCP-пресетов около минуты и выглядел
зависшим.

Теперь Discord одновременно проверяется через:

- `https://discord.com/api/v10/gateway`;
- `https://gateway.discord.gg/`;
- `https://cdn.discordapp.com/`.

Любой реальный HTTP-ответ доказывает, что DNS/TCP/TLS дошли до Discord, поэтому
коды `403` и `404` тоже считаются успешной доступностью. Первый успешный адрес
сразу завершает проверку и отменяет остальные запросы.

YouTube аналогично имеет три адреса:

- `https://www.youtube.com/generate_204`;
- `https://i.ytimg.com/generate_204`;
- `https://youtubei.googleapis.com/generate_204`.

После этого исправления контрольный запуск без VPN намеренно не повторялся:
пользователь попросил не раздувать текущий чат. Сборка, unit-тесты и отдельный
HTTP smoke-test прошли.

## 3. Интерфейс

Главное окно:

- WPF, фиксированный размер `460x450`;
- без консоли;
- без лишних подписей состояния на главном экране;
- основная кнопка показывает «Включить», «Запуск» или «Отключить»;
- карточки только Discord и YouTube;
- у Discord три канала: текст, медиа, голос;
- у YouTube два видимых канала: сайт и видео;
- индикаторы каналов отрисовываются WPF-векторами, а не размытыми PNG;
- окно отображается в панели задач;
- кнопка сворачивания теперь делает обычный `WindowState.Minimized`, а не
  скрывает окно;
- приложение одновременно остаётся доступным через системный трей;
- двойной щелчок по трею восстанавливает окно.

Проверка после последней сборки:

- `KROT.exe` запустился и отвечал;
- MainWindowHandle был ненулевым;
- UI Automation показал только `Discord`, `YouTube`, `Автозапуск` и основную
  кнопку;
- Win32 extended style: `APPWINDOW=True`, `TOOLWINDOW=False`.

### Цвета каналов

- серый — выключено, нет данных или весь интернет недоступен;
- жёлтый — запуск, проверка, поиск или ожидание реального UDP-трафика;
- зелёный — рабочий прямой доступ или подтверждённый пресет;
- красный — подтверждённый отказ.

### Иконка окна и трея

Новый мастер сделан по утверждённому кроту. В иконке оставлены чёрная морда,
нос, блик и усы. Силуэт проверен в размерах 16, 20, 24, 32, 48 и 64 px.

Файлы:

- `assets/tray/krot-tray-off.ico` — серый нос;
- `assets/tray/krot-tray-on.ico` — зелёный нос;
- `assets/tray/krot-tray-off.png` — PNG-мастер выключенного состояния;
- `assets/tray/krot-tray-on.png` — PNG-мастер включённого состояния.

Состояния:

- `Off`, запуск, поиск, остановка и ошибка — серый нос;
- `Running` и `PartialFailure` — зелёный нос.

ICO содержит слои 16, 20, 24, 32, 40, 48, 64, 128 и 256 px.
`krot-tray-off.ico` также является иконкой EXE. WPF-иконка окна и NotifyIcon
переключаются синхронно при изменении `MainWindowViewModel.AppState`.

Мастер получен встроенным ImageGen по референсу
`assets/mole/krot_mascot_preview.png`, затем однотонный фон удалён локально.
Выключенная версия — точная перекраска носа, поэтому геометрия при переключении
не прыгает.

## 4. Архитектура процессов

### `KROT.exe`

- обычный пользовательский WPF-процесс;
- читает и атомарно сохраняет пользовательские настройки;
- мигрирует старую схему настроек `v1` в `v2` и удаляет устаревшие сервисы;
- опрашивает локальную службу каждые три секунды;
- во время переходного состояния опрашивает чаще через события IPC;
- отображает независимые статусы каналов;
- управляет автозапуском GUI;
- показывает окно логов и ссылки «О приложении».

### `KROT.Service.exe`

- Windows Service от `LocalSystem`;
- Debug-служба называется `KROTZapret`;
- принимает только версионированные команды Named Pipe;
- протокол IPC сейчас `v3`;
- имя pipe содержит SID активного пользователя;
- ACL разрешает активного пользователя, локальных администраторов и
  `LocalSystem`;
- владеет runtime-процессами и их Job Object;
- хранит активную сессию, статусы каналов и сетевой fingerprint;
- запускает поиск, мониторинг и ремонт пресетов.

### Runtime-роли

`main`:

- `winws.exe`;
- Zapret 1 `v72.13`;
- TCP/TLS для Discord и YouTube.

`voice`:

- `winws2.exe`;
- активный Zapret 2 `v1.0.3`;
- YouTube QUIC;
- Discord Voice/STUN;
- Lua-обёртка `krot-auto.lua` над оркестратором `circular`.

Zapret 2 `v1.0.2` лежит рядом как предыдущая версия, но автоматический fallback
между `v1.0.3` и `v1.0.2` ещё не реализован.

## 5. Каталог стратегий

Определён в:

- `src/KROT.Zapret/Profiles/BuiltInStrategyCatalog.cs`;
- `src/KROT.Zapret/Profiles/BuiltInPresetCatalog.cs`.

Количество:

- TCP/TLS: 16;
- YouTube QUIC: 8;
- Discord Voice: 10.

Значения по умолчанию:

- TCP: `tcp-01-alt-fakedsplit-ts`;
- QUIC: `quic-01-google-r6`;
- Voice: `voice-01-fake-r2`.

TCP-поиск:

1. сохранённый профиль текущей сети;
2. прямой доступ;
3. остальные стратегии по очереди;
4. первый подтверждённый результат сохраняется.

UDP:

- Zapret 2 сам вращает стратегию через `circular`;
- KROT получает строку `KROT_UDP_WINNER|channel|strategy`;
- победитель сохраняется в cache текущей сети;
- Voice становится зелёным только после входящего IP Discovery response;
- подтверждение живёт в рамках активной сессии и сбрасывается при остановке
  KROT, поэтому новый запуск снова ждёт реального голосового подключения.

## 6. Файлы состояния и логи

Пользователь:

- `%LocalAppData%\KROT zapret\settings.json`;
- `%LocalAppData%\KROT zapret\settings.json.bak`;
- `%LocalAppData%\KROT zapret\logs\`.

Служба:

- `%ProgramData%\KROT zapret\service-state\logs\krot-current.log`;
- `%ProgramData%\KROT zapret\service-state\preset-cache.json`.

`preset-cache.json` не входит в Git. На текущем компьютере во время старого
ложного Discord-теста мог сохраниться последний TCP-пресет, подтверждённый уже
после возврата VPN. Новый probe при следующем запуске проверит сохранённый
вариант. Если потребуется полностью чистый подбор, cache можно удалить только
при остановленной службе.

Схема пользовательских настроек сейчас `v2`. При первом запуске старый
`settings.json` автоматически переписывается: неизвестные и дублирующиеся
сервисы удаляются, остаются только Discord и YouTube.

## 7. Runtime и целостность

Manifest:

- `third_party/zapret/runtime-manifest.json`.

В нём перечислены:

- Zapret 1 `v72.13`;
- Zapret 2 `v1.0.3`;
- Zapret 2 `v1.0.2`;
- WinDivert DLL/driver;
- Lua-файлы;
- KROT Lua wrapper;
- SHA-256 и источники.

Перед запуском `RealZapretProcessManager` проверяет manifest и SHA-256
перечисленных файлов. Процессы запускаются с маркером владения, PID, временем
старта и хэшем EXE. Глобальное завершение чужих `winws` по имени запрещено.

## 8. Сборка и локальный запуск

Требования:

- Windows 10/11 x64;
- .NET Framework 4.8 Developer Pack или подходящий .NET SDK;
- PowerShell;
- права администратора для установки Debug-службы.

Полная Debug-сборка и тесты:

```powershell
.\scripts\build.ps1 -Configuration Debug
```

Установка/обновление Debug-службы:

```powershell
.\scripts\install-debug-service.ps1
```

Удаление Debug-службы:

```powershell
.\scripts\uninstall-debug-service.ps1
```

GUI:

```text
src\KROT.App\bin\x64\Debug\net48\KROT.exe
```

## 9. Важные пользовательские решения

- Пока работать локально в Debug.
- Не публиковать текущие изменения без отдельной команды.
- Репозиторий в итоге должен быть публичным.
- Описание проекта и пользовательские тексты — короткие, по-русски, без
  канцелярита.
- Telegram не поддерживать.
- Сервис нейросетей не поддерживать.
- Консоль и технический статус на главном экране не показывать.
- Основная кнопка: «Включить» → «Запуск» → «Отключить».
- Не заставлять пользователя ловить тайминги: журналы должны сохранять события.
- Для разных провайдеров нужен широкий, но контролируемый каталог пресетов.
- Постоянный мониторинг должен быть лёгким и не путать полный обрыв сети с
  отказом отдельного сервиса.
