## 1. Цель продукта

KROT zapret — простая Windows-утилита для доступа к двум сервисам:

- Discord;
- YouTube.

Пользователь не выбирает стратегии, порты, фильтры и версии движка. Он отмечает
нужные сервисы и нажимает одну основную кнопку. Вся техническая конкретика
остаётся в ограниченных по размеру локальных журналах.

KROT не является VPN, не поднимает собственные серверы и не меняет системный
прокси. Обход выполняется локальными процессами Zapret только для выбранных
сервисов.

## 3. Пользовательский интерфейс

Главное окно:

- WPF, `.NET Framework 4.8`, x64;
- размер `400 × 320`, без изменения размера;
- без стандартной рамки, с собственными кнопками информации, сворачивания и
  закрытия;
- две строки сервисов: Discord и YouTube;
- одна основная кнопка: «Включить», «Отменить» или «Отключить»;
- автозапуск расположен в одной строке с собственной галочкой;
- окно сворачивается в системный трей;
- обычное закрытие выполняет остановку runtime и службы, затем завершает GUI.

Окно «О приложении»:

- помещается без прокрутки;
- показывает версию из метаданных сборки, сейчас `1.0`;
- содержит RU/EN, галочку подробных логов, просмотр журнала;
- содержит ссылки `KROT zapret` и `Zapret`;
- показывает лицензию `KROT zapret · MIT`.

### Индикаторы

Состояния каналов:

- `Disabled` / `Unknown` — серый;
- `WaitingForActivity` — статический жёлтый;
- `Testing` / `Searching` — пульсирующий жёлтый;
- `WorkingDirect` / `WorkingPreset` — зелёный;
- `Failed` — красный.

Discord:

- `text`;
- `media`;
- `voice`.

YouTube:

- `site`;
- `video`.

Для Discord Voice:

- до появления UDP-трафика показывается «Зайдите в голосовой канал»;
- после маркера начала потока — «Проверяю подключение» и пульсация;
- подтверждённый входящий ответ переводит канал в зелёный;
- отсутствие подтверждения после перебора переводит канал в красный;
- новый голосовой поток запускает проверку заново.

### Маскот

Крот построен в `KrotMascot.xaml` отдельными слоями:

- силуэт;
- шахтёрская каска;
- фонарь с отдельными линзой, свечением и лучом;
- неподвижные открытые глаза;
- отдельные закрытые веки для моргания;
- нос;
- усы;
- лапы.

Пассивная анимация срабатывает примерно каждые 3–5 секунд. Во время проверки
хотя бы одного канала крот остаётся неподвижным, фонарь плавно сканирует
пространство из стороны в сторону, а линза и луч мягко пульсируют.

### VPN и прокси

Служба проверяет:

- активные VPN-подобные сетевые адаптеры;
- системный прокси Windows.

При обнаружении рядом с кротом появляется облачко
«Отключи VPN/прокси». После исчезновения внешнего туннеля выполняется
внеплановая проверка каналов. Технические проверки не требуют отдельного
элемента в основном интерфейсе.

## 4. Архитектура процессов

### GUI

`KROT.exe`:

- работает без повышения прав;
- хранит пользовательские настройки и GUI-журнал;
- управляет треем, локализацией и отображением состояний;
- отправляет команды службе через Named Pipe;
- опрашивает состояние службы примерно раз в три секунды;
- при выходе отправляет команду `shutdown`.

### Windows-служба

`KROT.Service.exe`:

- установлена как `KROTZapret`;
- работает от `LocalSystem`;
- имеет тип запуска `Manual`;
- запускается GUI по требованию;
- принимает команды только через версионированный Named Pipe;
- останавливает runtime и себя после команды GUI;
- имеет watchdog: при потере heartbeat GUI runtime и служба завершаются.

IPC protocol version: `5`.

Имя pipe включает SID интерактивного пользователя. ACL разрешает доступ:

- этому пользователю;
- локальным администраторам;
- `LocalSystem`.

Входящие и исходящие JSON-строки имеют ограничения размера, глубины и времени
чтения. Неизвестные команды и несовпадающая версия протокола отклоняются.

### Runtime

Две независимые роли:

- `main` — TCP/TLS для Discord и YouTube на Zapret 1;
- `voice` — UDP/QUIC/STUN/Discord Voice на Zapret 2.

Перезапуск `voice` не должен затрагивать `main`.

`RealZapretProcessManager`:

- проверяет manifest;
- проверяет SHA-256 каждого обязательного файла;
- запускает только разрешённые executable и аргументы;
- хранит PID, время запуска, SHA-256 и ownership marker;
- помещает процессы в Windows Job Object с `KILL_ON_JOB_CLOSE`;
- не завершает процессы глобально по имени;
- выгружает WinDivert только при совпадении пути драйвера с проверенным runtime
  KROT.

Runtime в Debug:

- Zapret 1 `v72.13`;
- Zapret 2 `v1.0.3`;
- резервный комплект Zapret 2 `v1.0.2` пока присутствует, но автоматический
  fallback между версиями ещё не реализован.

## 5. Подбор стратегий

Общий порядок:

1. Проверить сохранённый профиль текущей сети.
2. При его отсутствии или отказе проверить прямой доступ.
3. Если прямой доступ не работает и VPN не обнаружен, перебирать каталог.
4. Сохранить победителей по отпечатку сети.
5. Во время работы выполнять лёгкий health monitor.

В текущем каталоге:

- 16 TCP/TLS-вариантов;
- 8 YouTube QUIC-вариантов;
- 10 Discord Voice-вариантов.

Отпечаток сети строится без хранения чувствительных исходных данных. В кэше
сохраняются только SHA-256 отпечатка и идентификаторы выбранных стратегий.

Смена адаптера, Wi-Fi, VPN или прокси будит сетевой монитор. После короткой
стабилизации выполняется внеплановая проверка. Полный обрыв интернета не должен
ошибочно запускать бесконечный подбор.

## 6. Настройки и журналы

Пользовательские данные:

- `%LocalAppData%\KROT zapret\settings.json`;
- `%LocalAppData%\KROT zapret\logs\`.

Служебные данные:

- `%ProgramData%\KROT zapret\service-state\preset-cache.json`;
- `%ProgramData%\KROT zapret\service-state\logs\`.

Настройки:

- сохраняются через временный файл;
- сбрасываются на диск;
- заменяются атомарно;
- имеют резервную `.bak`;
- ограничены размером 1 MiB;
- текущая schema version: `3`.

Логи:

- GUI и служба ведут раздельные журналы;
- обычные события и ошибки пишутся всегда;
- подробные probe/runtime-события пишутся только при включённой галочке;
- максимум пять файлов на область;
- максимум 2 MiB на файл;
- общий предел примерно 10 MiB для GUI и 10 MiB для службы;
- отдельная запись ограничивается и очищается от управляющих переносов.

## 7. Проверка обновлений

GUI обращается к публичному GitHub Releases API:

- один раз после открытия окна;
- затем раз в 24 часа, пока приложение остаётся запущенным или находится в
  трее.

При более новой числовой версии:

- справа от основной кнопки появляется жёлтая иконка загрузки;
- подсказка содержит номер и краткое очищенное описание;
- клик открывает HTTPS-страницу релиза на `github.com`;
- автоматической загрузки или установки нет;
- tray-напоминание повторяется не чаще раза в три дня.

Сбой GitHub не влияет на runtime и попадает только в подробный лог.

## 10. Что не подтверждено этим аудитом

VPN во время работы Codex оставался включён. Поэтому в этом checkpoint не
перепроверялись реальные результаты обхода Discord и YouTube без VPN.

Ранее рабочие стратегии и голосовой UDP-поток были проверены вручную, но перед
публичным релизом необходимо повторить на нескольких провайдерах:

1. Discord text/media.
2. Discord Voice с входом и выходом из канала.
3. YouTube site/video/QUIC.
4. Смена Wi-Fi.
5. Полный обрыв и восстановление сети.
6. Включение и выключение VPN во время активного KROT.

Жёлтая иконка обновления проверена тестами и XAML-сборкой, но не могла появиться
в живом GUI: в GitHub пока нет обычного числового релиза новее `1.0`.

## 12. Основные команды разработки

Строгая Debug-сборка:

```powershell
dotnet build KROT.sln -c Debug -p:Platform=x64 -p:TreatWarningsAsErrors=true
```

Тесты:

```powershell
dotnet test KROT.sln -c Debug -p:Platform=x64 --no-build
```

Проверка форматирования:

```powershell
dotnet format KROT.sln --verify-no-changes --no-restore
```

Установка свежей Debug-службы без запуска:

```powershell
.\scripts\install-debug-service.ps1 -NoStart
```

Запуск GUI:

```text
src\KROT.App\bin\x64\Debug\net48\KROT.exe
```
